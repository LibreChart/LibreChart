# Quickstart — EMR Station Transitions

Walkthrough for a developer or QA to verify the feature end-to-end against the four user stories. Assumes the implementation is deployed (per `tasks.md` to be generated by `/speckit.tasks`).

## Prerequisites

- Local DDEV environment running (`ddev status` shows the project up)
- Seeded sample data already loaded: 220 patients + 230 visits + 3 clinic sites + 102 drug inventory records
- One user account per clinical role (or admin to bypass)

## Setup steps after pulling this branch

```bash
# 1. Install the new base field
ddev drush updb -y

# 2. Backfill current_station for the 230 existing seeded visits
ddev drush php:script scripts/backfill_current_station.php

# 3. Import config (form display + menu link)
ddev drush config:import -y

# 4. Clear caches
ddev drush cache:rebuild
```

Expected output of step 2:
```
Backfilled current_station: 230 visits updated, 0 skipped.
```

## User Story 1: Station indicator on the visit form

1. Log in as admin.
2. Visit `/admin/content/visits`, open any in-progress visit's edit page.
3. **Expect**: a horizontal strip across the top of the form showing 7 station badges (Registration → Triage → Lab → Clinical → PT → Pharmacy → Teaching). Exactly one badge is highlighted (the current_station), and the strip uses the colors from `patient-flow.md` (blue/green/yellow/purple/orange/pink/green).
4. Open a `status = complete` visit. **Expect**: all 7 stations rendered as "completed" (dimmed/check-marked); no "current" station highlighted.

Pass = strip present, current station highlighted, color scheme matches.

## User Story 2: Advance to next station

1. Log in as the `triage_nurse` role.
2. Open any visit currently at `triage`.
3. **Expect**: a secondary button labelled "Send to Lab Orders & Results" next to "Save".
4. Click "Send to Lab Orders & Results".
5. **Expect**:
   - Status message: "Transitioned … to Lab Orders & Results."
   - Redirected back to the visit form (or the patient chart) with the station strip now highlighting Lab.
   - `ddev drush sqlq "SELECT current_station FROM visit WHERE vid=<id>"` returns `lab`.
   - `ddev drush sqlq "SELECT revision_log_message FROM visit_revision WHERE vid=<id> ORDER BY revision_id DESC LIMIT 1"` returns "Transitioned from Triage to Lab Orders & Results by …"
6. Switch to the `clinician` role; open the same visit. **Expect**: no "Send to next" button visible (the visit is at `lab`, not `clinical`).

Pass = transition button visible only to station owner, click advances field, revision logged.

## User Story 3: Floor view

1. Open `/floor` as any authenticated clinical user.
2. **Expect**: 7 columns in workflow order, each labelled with the station name and a `(n)` count.
3. **Expect**: each in-progress visit appears in exactly one column matching its `current_station`.
4. **Expect**: complete visits are absent.
5. Click a visit name. **Expect**: lands on `/visit/{vid}/edit`.

Verify with SQL:
```bash
ddev drush sqlq "SELECT current_station, COUNT(*) FROM visit WHERE status != 'complete' GROUP BY current_station;"
```
The counts must match the `(n)` numbers in the column headers.

Pass = columns render in order, counts match SQL, complete visits excluded.

## User Story 4: PT skip

1. As an admin, find a visit at `clinical` and set `pt_referral` to false. Save.
2. Log in as `clinician`, open the visit.
3. **Expect**: the secondary button reads "Send to Pharmacy Dispensing" (not "Send to Physical Therapy").
4. Click the button. **Expect**: `current_station = pharmacy`. Floor view shows the visit in the Pharmacy column.

Repeat with `pt_referral = true`. Expect button reads "Send to Physical Therapy" and the transition lands on `pt`.

Pass = PT correctly skipped or included based on referral.

## User Story 5: Flexible picker — any-to-any routing

1. Log in as `clinician`.
2. Open a visit at Clinical Evaluation with `pt_referral = true`.
3. **Expect** in the form actions area: the existing "Send to next station" button (which would send to PT) PLUS a station picker labelled "Or send to a specific station" with options for Registration, Triage, Lab Orders & Results, Physical Therapy, Pharmacy Dispensing, Teaching & Referrals (Clinical Evaluation is excluded).
4. Select "Pharmacy Dispensing" from the picker, click "Send".
5. **Expect**:
   - Status message: "Visit sent to Pharmacy Dispensing."
   - Redirect to the patient chart.
   - `ddev drush sqlq "SELECT current_station FROM visit WHERE vid=<id>"` returns `pharmacy`.
   - `ddev drush sqlq "SELECT revision_log_message FROM visit_revision WHERE vid=<id> ORDER BY revision_id DESC LIMIT 1"` returns `Transitioned from Clinical Evaluation to Pharmacy Dispensing by …`.
   - Watchdog has a `notice` entry: `picker transition: vid=<id> from=clinical to=pharmacy uid=<uid>`.

Pass = picker visible, selection writes the chosen target (bypassing PT despite `pt_referral = true`), revision + watchdog notice created.

### Edge cases for US5

- **Backward routing**: as `pharmacist`, use the picker to send a Pharmacy visit back to Triage. Verify it lands at Triage; revision logged.
- **Non-owner sees nothing**: log in as `pharmacist`, open a visit at Triage. Confirm neither the linear button nor the picker is in the rendered HTML — only "Save".
- **Tampered submission**: log in as `pharmacist` (still not owner of Triage). Open dev tools, inject a `station_picker` form element, set a value, submit. Expect: page reloads with a form error "You may not transition this visit from its current station." Visit unchanged. Watchdog `warning` entry recorded.
- **Same-station no-op**: programmatically POST a submission with `station_picker = <current>`. Verify: no entity save, no revision, no error.
- **Completed visit**: open a visit with `status = complete`. Expect: neither linear button nor picker rendered. Admin user sees a "Reopen visit" link instead.
- **PT-skip is shortcut-only**: at a Clinical visit with `pt_referral = false`, the linear button reads "Send to Pharmacy Dispensing" (PT skipped). The picker still includes Physical Therapy as a selectable option. Selecting `pt` from the picker writes `current_station = 'pt'` despite `pt_referral = false`.
- **Picker does not complete**: route into Teaching via the picker. Verify `status` stays `in_progress` (the picker does not flip status). Completion still requires the linear shortcut's terminal click.

## Failure modes to verify

- Two browsers transitioning the same visit concurrently: the second one gets the existing optimistic-locking error from `Visit::preSave`.
- Anonymous user hitting `/floor`: redirected to login.
- `clinician` user clicking the visit form's transition button when the visit is at `pharmacy`: not possible — button is not rendered for non-owners.

## Rollback

If the feature needs to be removed:
1. `ddev drush php:script scripts/backfill_current_station.php --revert` (sets `current_station` to NULL; script supports a revert flag).
2. Revert the `librechart_visit_update_9001` hook by running the corresponding `librechart_visit_update_9002` that uninstalls the field storage definition.
3. Remove the new files listed in `plan.md`.
